# F300 Speedhive Bot — Pilot Setup

This is the first pilot version of the F300 Speedhive importer.

It deliberately starts as a **manual GitHub Action** so one real Lydd event can be inspected before a Sunday schedule is enabled.

## What it does

1. Opens a Speedhive Event Results event.
2. Reads its sessions using the public Speedhive results endpoints.
3. Looks for F300 Heat 1, Heat 2, Heat 3 and Final.
4. Extracts driver number, driver name, result and best lap.
5. On a live run, sends one signed batch to the F300 Apps Script backend.
6. Apps Script matches the Speedhive kart number/name to the `Drivers` sheet.
7. It updates `Race Results` directly.
8. The existing points formulas calculate the F300 points/weekend total.
9. Apps Script immediately triggers the existing GitHub data update workflow.

The importer will not invent a driver match. An unknown number/name or a number/name disagreement is skipped and recorded in `Timing Import Log`.

## Required setup

### 1. Apps Script

Replace `Code.gs` with `F300_AppsScript_Timing_Bot_Auto_Sync.gs`.

Save, then run:

`setupDriverFeatures`

once.

Then run:

`createTimingBotSecret`

once.

Open the execution log and copy the value after:

`F300_TIMING_BOT_SECRET=`

Do not put this secret in the Sheet or in public repository files.

After replacing `Code.gs`, update the existing Web App deployment:

Deploy → Manage deployments → Edit → New version → Deploy

### 2. GitHub secret

Repository → Settings → Secrets and variables → Actions → Secrets

Create:

`F300_TIMING_BOT_SECRET`

Paste the exact secret generated by Apps Script.

`F300_DATA_URL` is already used by the existing data updater and is also used by this importer.

### 3. Upload bot files

Add:

`.github/workflows/import-speedhive-results.yml`

`scripts/import-speedhive-results.py`

Do not replace the existing `update-championship-data.yml` workflow.

## First test

Open today's event in Speedhive and copy the URL. A normal archived event URL looks like:

`https://speedhive.mylaps.com/events/1234567`

Then:

GitHub → Actions → Import Speedhive Results → Run workflow

Use:

- Event: paste the Speedhive event URL
- Round: `4`
- Dry run: `true`

The Action log will list every F300 session/result it recognizes but will not change Google Sheets.

If the four F300 sessions and drivers look correct, run it again with:

Dry run: `false`

That second run writes directly to `Race Results`.

## After the pilot works

The next step is to save Lydd's Speedhive organization ID as the GitHub variable:

`SPEEDHIVE_ORG_ID`

Then the workflow can be put on a Sunday race-day schedule and discover the newest Lydd event automatically, removing the need to paste an event link.
